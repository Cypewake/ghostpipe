## 2. 总体架构

```
外部用户 ──► VPS:10022 (server 映射端口)
                │ server
                │ 控制连接(信令) + 数据通道(Stream)
                ▼
             内网 client ──► localhost:22
```

- 两个二进制：`ghostpipe-server`（公网 VPS）、`ghostpipe-client`（内网机器，主动出网）。
- client 启动时按配置 REGISTER 若干隧道（`remote_port → local_target`）。
- 语言：Go 1.26（goroutine 模型天然适配多路复用；单二进制跨平台）。

## 3. 帧协议（自定义协议本体）

### 3.1 帧头（13 字节定长，网络字节序/大端）

```
+--------+-----+------+-------+-----------+----------------+
| Magic  | Ver | Type | Flags | StreamID  | Length         |
| 2B     | 1B  | 1B   | 1B    | 4B        | 4B             |
| 0x4750 | 会话 | 见表 | 恒0   | 流标识    | 仅计Payload    |
+--------+-----+------+-------+-----------+----------------+
Payload: ≤ 16384 字节（16KB）
```

**编解码规则：**
- Magic ≠ 0x4750 → 协议违规，立即断连。
- Length 先校验后分配缓冲（先校验 ≤16KB 再 make）——防恶意 Length 预分配耗尽内存。
- Flags 发送恒 0；接收端**忽略** Flags 值（前向兼容，未来扩展用）。
- Ver：握手时协商（见 3.3），会话内每帧复验，与会话 Ver 不符 = 协议违规断连。

### 3.2 信令类型表

| Type | 名称 | 方向 | Payload |
|---|---|---|---|
| 0x01 | AUTH_REQ | S→C | nonce_s(16B 随机) |
| 0x02 | AUTH_RESP | C→S | nonce_c(16B) + hmac_c(32B) |
| 0x03 | AUTH_OK | S→C | hmac_s(32B) |
| 0x04 | DATA_BIND | C→S | data_token(32B) |
| 0x10 | REGISTER | C→S | remote_port(u16) + target(u16 长度前缀字符串) + instance_id(8B) |
| 0x11 | REGISTER_OK | S→C | 空 |
| 0x12 | UNREGISTER | C→S | remote_port(u16) |
| 0x20 | OPEN | S→C | M1：remote_port(u16) + data_token(32B)；M2：remote_port(u16)，StreamID=新流 |
| 0x21 | OPEN_OK | （v1 保留未用） | — |
| 0x22 | OPEN_ADDR | 双向 | target（u16 长度前缀字符串，SOCKS5 动态目标；发起方=代理入口侧，接收方在己侧拨号） |
| 0x30 | DATA | 双向 | 透传字节（≤16KB） |
| 0x31 | CREDIT | 双向 | delta(u32)；StreamID=0 表示连接级 |
| 0x40 | CLOSE | 双向 | 空（双向关闭，v1 无半关闭） |
| 0x50 | ERROR | 双向 | code(u16) + msg |
| 0x60/0x61 | PING/PONG | 双向 | 空 |

**错误码**：auth-failed / ver-unsupported / dup-handshake / remote-refused / resource-limit / id-exhausted / proto-violation / tunnel-conflict（实现期补入，v1 未触发，前向保留）。

### 3.3 版本协商

- client 携带自身 Ver 发起；server 判定：`client_ver ≤ server_ver` → 接受，会话锁定为 client_ver（**新版 server 兼容旧 client**）；`client_ver > server_ver` → ERROR(ver-unsupported) 断连。
- 不做多版本共存、不做能力位协商（v1 简化，文档声明）。

## 4. 认证与加密（双向）

### 4.1 时序（TLS 建立后、任何其他信令前，总时限 10 秒防 slowloris）

```
S→C  AUTH_REQ{nonce_s}                          # 16B CSPRNG
C→S  AUTH_RESP{nonce_c, hmac_c}                 # hmac_c = HMAC-SHA256(PSK, "c"‖nonce_c‖nonce_s)
S→C  AUTH_OK{hmac_s}                            # hmac_s = HMAC-SHA256(PSK, "s"‖nonce_c‖nonce_s)
```

- **双向认证**：client 校验 hmac_s（防恶意 server / 中间人冒充）；server 校验 hmac_c。
- **防重放**：nonce 单次使用（内存已消费集合），不引入 timestamp（challenge 本身即一次性，timestamp 徒增时钟偏移问题——第一轮 #6 修正）。
- PSK：高熵配置项（建议 ≥32 字节随机），不上网络，离线爆破不可行即满足威胁模型。
- 复用同一信令连接发第二次 AUTH = dup-handshake 错误断连。

### 4.2 TLS 策略

| 规则 | 内容 |
|---|---|
| 默认 | TLS 1.3 开启（Go crypto/tls） |
| 证书 | 自签 + **client 端 SPKI 指纹 pinning**（`--tls-fingerprint` 必填，未配置拒绝连接） |
| 例外 | `--insecure-tls` 显式关闭 TLS，启动打印醒目警告 |
| 降级 | **无静默降级**：不做"TLS 失败回退明文"；两端配置显式声明模式 |

## 5. 数据通道

### 5.1 Stream 抽象（M1/M2 通用，消除 M1→M2 重写）

```go
type Stream interface {
    Read(p []byte) (int, error)
    Write(p []byte) (int, error)
    Close() error
}
```

- M1：`ConnStream` —— 每个转发会话一条独立 TCP 数据连接。
- M2：`MuxStream` —— 多路复用流。
- **上层转发逻辑（外部连接 ↔ Stream 的双向 pump）只面向 Stream 接口，M1→M2 零改动。**

### 5.2 M1 数据连接绑定（第一轮 #4 修正；方向按实现定稿 —— server 驱动）

```
1. 外部连接到达 server 的 remote_port（server 先缓存该连接）
2. server 生成 data_token(32B CSPRNG，单次/10s 过期)
   → OPEN{remote_port, data_token}       （控制连接，S→C）
3. client 新拨 TCP → 首帧 DATA_BIND{data_token}（TLS 信道内传输）
4. server 原子消费 token（mutex 保证并发出示同 token 仅一次成功）
   → 与等待中的外部连接对接 → 进入纯字节转发
```

- M1 数据连接**旁路帧级流控**（纯 TCP 流控），CREDIT 帧仅 M2 语义。
- token 未消费被清理的时机：过期(10s)、实例替换、控制连接断开 → 同时关闭等待中的外部连接。
- client 数据连接 TCP 拨号失败 → 丢弃 token，重新 OPEN 取新 token 重试。

### 5.3 M2 多路复用与流控

| 规则 | 内容 |
|---|---|
| StreamID 分配 | client 奇数 / server 偶数，各自单调递增，**永不复用** |
| 耗尽处理 | 2^31-1 触顶 → ERROR(id-exhausted) + 连接级 teardown（实际长连接几乎不可能触顶，协议必须写明） |
| 并发上限 | 每连接并发流 ≤256；pending token ≤64；超限 ERROR(resource-limit) |
| 并发模型 | 每连接**单读循环** → 按 StreamID 分发到流缓冲（sync.Cond，缓冲上界=流级窗口）；每流**两个方向独立 pump** goroutine（单循环收发必死锁——第二轮 #5 修正）；每连接一把写锁串行化帧写入 |
| 流控（双层信用） | 流级窗口 256KB + 连接级窗口 1MB；发送消耗信用，CREDIT 补充 |
| 信用记账 | **连接级**：帧被读循环读入内存后即回 CREDIT（只保护 socket 读取缓冲）→ 流关闭不泄漏连接级信用；**流级**：本地应用消费后回 CREDIT → 流关闭时未消费信用随流作废（只影响该流） |
| 控制帧豁免 | AUTH_*/REGISTER*/OPEN*/CREDIT/CLOSE/ERROR/PING/PONG **不受任何窗口约束**（防"双向等 CREDIT"死锁——第二轮 #3 修正） |
| 迟到帧 | 已关闭 stream_id 的 DATA/CREDIT → **静默丢弃 + 计数日志**（关闭 ID 集合保留至连接结束；按违规断连会误杀 in-flight CLOSE 竞态——第二轮 #8 修正） |

## 6. 生命周期

| 场景 | 规则 |
|---|---|
| 心跳 | 每 5s PING，5s 内未回 PONG 计一次失败，**连续 3 次失败断开**；最坏故障感知 ~30s（文档如实标注，不夸大） |
| 数据连接保活 | TCP keepalive 30s；**不设应用层空闲超时**（5 分钟空闲超时会杀 SSH 长会话——第二轮 #9 修正）；资源兜底靠连接数上限 |
| 重连 | 指数退避 1s×2 + 随机抖动，上限 60s |
| REGISTER 替换 | **同 remote_port 的新 REGISTER 无条件原子替换**旧映射（不看 instance_id——instance_id 仅用于日志观测；第二轮 #1 修正）；旧实例的流、pending token、等待中的外部连接全部立即回收 |
| 断连窗口外部连接 | server 端直接 RST（不做排队，文档声明） |
| 优雅退出 | client 发 UNREGISTER{remote_port} 后再断连；被 kill 则靠心跳收敛（~30s，文档如实） |
| 错误回传 | client 连本地目标失败 → ERROR{stream_id, remote-refused} → server 关闭对应外部连接（happy path 之外的路径也走信令） |
| 半关闭 | v1 不支持（CLOSE=双向关闭），文档明示；SSH/HTTP 场景无影响 |

## 8. 威胁模型（作品集必备章节）

| 威胁 | 对策 |
|---|---|
| 被动嗅探 | TLS 1.3 默认 |
| 主动 MITM | SPKI pinning + 双向 HMAC |
| 恶意 server 冒充 | client 校验 hmac_s |

## 10. 实现偏差记录（设计 → 代码，全部已折回本文档）

> 编码过程中发现的设计缺口/方向性修正。原则：**偏差必须回写设计文档**，保持"文档即真相"。

| # | 偏差点 | 设计原稿 | 实现定稿 | 原因 |
|---|---|---|---|---|
| 1 | **OPEN 方向反转** | OPEN 由 client 发起（C→S），OPEN_OK 由 server 回 | **OPEN 由 server 发起（S→C）**；OPEN_OK v1 未用（保留）；新增 OPEN_ADDR（C→S，SOCKS5 动态目标） | 隧道语义下外部流量先到 server，"谁需要本地拨号谁收 OPEN"才是自然方向；§3.2 与 §5.2 已同步改定 |
| 2 | **认证先发方** | 时序图未明确"谁先出第一帧" | **server 永远先发 AUTH_REQ**，client 只等 challenge；M1 数据连接上 client 需先吞掉一条迟到 challenge 再进纯转发 | 消除 peek-frame 竞态：若 client 先发首帧、server 先 peek，双方互等死锁；server 先发彻底消除该类竞态 |
| 3 | **跨会话端口接管** | REGISTER 原子替换仅限"同会话"语义 | 新增**全局端口归属表** `ports[port]*session`：新会话 REGISTER 同端口时，由 server 从旧会话侧摘除该隧道（关闭旧 listener、清旧 pending），完成僵尸接管 | kill -9 后 client 快速重连时旧会话尚未被心跳判死，仅靠会话内替换无法回收旧实例端口 |
| 4 | **错误码补充** | 7 个错误码 | 8 个：补 `tunnel-conflict(8)`（v1 未触发，前向保留） | 编码期预留，避免未来加码破坏二进制兼容 |
| 5 | **心跳判死语义** | "5s 一跳，连续 3 次失败断开" | "5s 一跳，**15s 内无任何入帧**即断开"（LastRecv 原子时间戳） | 语义等价（3 个周期）且实现更简单——任何入帧（DATA/CREDIT/PONG）都证明链路活，比逐次计数少一个状态机 |
| 6 | **M2 并发模型** | "每流两个方向独立 pump" | 单读循环 + **sendCh 队列 + 单 sender goroutine** 串行化全部出帧；读循环用非阻塞 trySend、应用路径用阻塞 sendAsync | net.Pipe 同步语义下实测死锁（20 流并发测试超时）：sync Send 在读循环内会被对端写阻塞反锁。队列化后全部测试通过 |
| 7 | **OPEN_ADDR 双向化 + 服务端 SOCKS5 入口** | OPEN_ADDR 仅 C→S（客户端 SOCKS5 → 服务端出网）；"访问客户端内网设备"仅靠端口转发 | OPEN_ADDR **双向**（发起方=代理入口侧，接收方在己侧拨号）；服务端新增 `-socks5` 入口（经 cur 会话下发 OPEN_ADDR S→C，客户端内网拨号）= frp socks5 插件等价方向 | 用户质疑驱动：外部经代理访问客户端内网任意设备是内网穿透的核心用法，仅端口转发（固定映射）覆盖不了动态目标；StreamID 奇偶规则天然支持双向（发起方按自身奇偶分配），mux 层零协议改动 |
